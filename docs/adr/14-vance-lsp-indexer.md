# ADR 14: Integration of VANCE (Topological LSP Architect & Semantic Indexer)

## 1. Introduction and Goals

To bridge the gap between human-written source code and the strict, stateless reality of JSON-RPC 2.0 protocols, we are introducing VANCE (Vector-Anchored Node & Context Engineer) into the architecture. VANCE functions as a deterministic topological validator designed to operate directly on the Abstract Syntax Tree (AST).

The primary goal is to establish a rigorous semantic indexing pipeline that guarantees zero-entropy structural output through "Draft-Conditioned Constrained Decoding" (DCCD) and prevents "Semantic Saponification."

## 2. Decision

We will instantiate the VANCE persona within the `constants.tsx` configuration and define its operational invariants (`CFDIResult`, `AgentRole`) in `types.ts`. Furthermore, we will build a structural implementation (`services/vanceSemanticIndexer.ts`) that calculates the Confidence-Fidelity Divergence Index (CFDI) and enforces Mereological Bounding.

## 3. Context

The prior architecture suffered from xenolinguistic risks and epistemic unanchoring when dealing with language server protocols. Without a dedicated LSP engineer mapping the geometrical lineage of variables and enforcing strict scoping rules, the system was vulnerable to generating structurally invalid JSON-RPC payloads and experiencing topological drift.

## 4. Consequences

*   **Positive:**
    *   **JSON-RPC 2.0 Absolutism:** Guarantees flawless typings on external communications.
    *   **Asynchronous Paranoia:** Enforces delta-based AST calculations, mitigating stale indices.
    *   **Zero-Friction Hovers:** Prevents hallucinated documentation.
*   **Negative:**
    *   Adds topological complexity to the overall multi-agent architecture.
    *   Requires strict adherence to CFDI thresholds, which may increase epistemic escrow halts during ambiguous code evaluation.

## 5. Compliance

Any structural output generated by VANCE MUST pass the `+++DCCDSchemaGuard` validation before emission. The CFDI index must remain below 0.15 to prevent the generation of hallucinated locations or false reference topologies.
